# PBC EMS 설계안

상태: 사용자 승인 (2026-10-16). 구현·배포 완료 문서가 아니다.
작성일: 2026-10-16 (Australia/Sydney).

## 1. 확인된 목표

사용자가 Jobber를 대체할 회사 전용 독립 EMS를 요청했다.
Next.js + Supabase를 사용하고 기존 PBC-Quote-cal과 EMS의 데이터는 분리한다.

요청 범위는 Create, Home, Schedule, Clients, Requests, Quotes, Jobs,
Invoices, Expenses, Timesheets이다.
Quotes에는 실제 운영 중인 PBC-Quote-cal의 계산과 견적 생성 기능을 반영한다.

기존 견적 앱을 변경하지 않고 새 EMS에서 필요한 계산·편집 기능을 재사용하는 안이다.
아래 세부 기능·권한·화면은 관찰 자료에 근거해 사용자가 승인한 구현 기준이다.

## 2. 접근법 비교와 권장안

| 안 | 방식 | 판단 |
| --- | --- | --- |
| A, 권장 | 새 EMS + 독립 Supabase + 계산/견적 모듈 이식 | 요청한 독립성, 명확한 권한·데이터 경계에 적합 |
| B | 기존 견적 앱 전체 복제 후 확장 | Jobber OAuth·write-back과 불필요한 구조까지 따라와 정리 범위 증가 |
| C | EMS에서 기존 견적 앱 연결 | 기존 로그인·데이터·장애에 의존해 독립 EMS 목표에 부적합 |

A를 권장한다. Jobber는 사용자 경험과 업무 흐름의 참고 자료이며 제품 코드는 새로 작성한다.
기존 계산 모듈은 출처 버전과 회귀 fixture를 기록해 이식한다.

## 3. 업무 흐름

고객/현장 → Request 접수·현장 점검 → Quote 작성·확정 → Job 생성 →
Visit 일정·작업자 배정 → 작업 진행·완료 → Invoice 발행·수금기록.

Expenses와 Timesheets는 Job/Visit에 연결할 수 있고 미연결 일반 기록도 허용한다.
Create는 생성 진입점, Home은 실제 레코드를 집계하는 화면이다.
견적상 인일, 배정 일정, 실제 근무 시간은 서로 별도 값으로 관리한다.

견적 없이 Job을 직접 생성할 수 있고, 기존 연결 관계는 상세 화면에서 추적한다.
반복 생성·네트워크 재시도는 같은 업무를 중복 생성하지 않는다.

## 4. 메뉴별 기능과 완료 조건

| 메뉴 | 기능 | 완료 조건 |
| --- | --- | --- |
| Create | Client/Request/Quote/Job/Invoice 빠른 생성. 비용·근무는 해당 화면에서 추가 | 어디서든 열고 취소 후 원래 위치·포커스로 복귀 |
| Home | 오늘/다가오는 방문, 새 요청, 견적 상태, 진행 작업, 청구 필요·연체·미수 집계 | 집계 숫자가 실제 필터 목록과 일치하고 선택 시 이동 |
| Schedule | 월/주/일·목록, 날짜 이동, 방문/점검/일반 일정, 종일 일정, 작업자 배정·필터, 미배정 목록 | 여러 날·여러 인원, 시각·종일·현지 날짜가 저장 후 유지 |
| Clients | 고객·회사, 연락처, 청구 주소, 여러 현장, 메모·태그, 검색·편집·보관, 관련 업무 이력 | 고객 변경과 과거 발행 문서 스냅샷이 분리됨 |
| Requests | 고객·현장, 요청 내용, 희망일, 현장 점검 일정·담당자, 상태, Quote/Job 연결 | 접수에서 현장 점검·견적까지 재입력 없이 연결 |
| Quotes | 원본 계산기·옵션·고객용 행·견적 템플릿, 복제, 버전, 미리보기, 인쇄/PDF, 발행/승인 기록, Job 전환 | 기존 계산 결과 일치, 내부 원가가 출력에 나타나지 않음 |
| Jobs | 견적에서 전환 또는 직접 생성, 작업 범위·담당자, 여러 방문, 메모, 작업 상태, 비용·근무 요약, 청구 연결 | 확정 계약과 실제 수행·비용을 구분하고 이력 추적 |
| Invoices | Job에서 행 복사 또는 직접 작성, 번호·발행/만기일, 세금·합계, 인쇄/PDF, 수금·잔액·연체 | 확정 청구액이 보존되고 중복 발행·수금 입력 충돌 방지 |
| Expenses | 날짜·분류·금액·설명·작성자·연결 작업·비공개 영수증, 검색·필터·합계·보관 | 권한 범위와 파일 접근을 검사하고 작업 실제 비용에 반영 |
| Timesheets | 작업자별 일/주, Job/Visit, 시작·종료·휴게·메모, 타이머·수동 입력·제출·승인 | 중복 타이머·음수/중복 시간 방지, 승인 이후 변경 추적 |

자재 카탈로그·단가·견적 템플릿 설정은 Quotes 안의 보조 화면으로 둔다.
사용자·회사 기본 정보는 관리 메뉴의 필수 설정만 둔다.
별도 Marketing, Pipeline, Insights, Apps, AI, 급여 계산 기능은 추가하지 않는다.

## 6. 데이터 모델과 금액 보존

| 영역 | 엔티티 |
| --- | --- |
| 회사·직원 | organizations, memberships |
| 고객·현장 | clients, properties |
| 요청 | requests |
| 견적 | quotes, quote_revisions, quote_lines, quote_calculations |
| 견적 설정 | products, pricing_settings, quote_templates |
| 작업·일정 | jobs, visits, visit_assignments |
| 청구 | invoices, invoice_lines, payments |
| 비용·근무 | expenses, time_entries |
| 감사 | activity_events, 첨부파일 메타데이터 |

회사 한 개를 먼저 지원한다. 회사 전환·다중회사 관리 UI는 만들지 않는다.
업무 테이블에는 organization_id를 넣고 부모/자식은 회사 경계까지 검증한다.
고객용 금액과 내부 계산은 권한 경계가 다른 테이블/서버 응답으로 분리한다.

견적 저장은 서버 재계산, 관련 행 저장, 버전 검사, 이력 기록을 하나의 트랜잭션으로 수행한다.
승인은 특정 revision과 선택 옵션을 고정한다.
승인 견적→Job 변환은 같은 revision의 중복 전환을 막는다.
Job의 확정 작업 범위·고객용 금액을 Invoice로 복사하며 현재 자재 가격으로 다시 계산하지 않는다.

초기 기본 청구는 작업 전체 잔액을 청구하는 방식이다.
동일 작업에 대한 중복 전액 청구를 막고, 취소 청구는 이력을 남긴다.
부분·진행·분할 청구는 별도 확정이 필요한 추가 범위로 남긴다.
수금은 외부 결제를 실행하는 기능이 아니라 이미 받은 금액의 기록이다.
원화/외화 자동 변환·카드 결제·급여 산출은 범위에 포함하지 않는다.

## 7. 상태 모델

상태를 한 필드에 모두 넣지 않고 저장 상태와 날짜·잔액으로 계산되는 표시를 구분한다.

| 영역 | 저장 상태 및 규칙 |
| --- | --- |
| Request | new → in_review → quoted → closed. 점검 미배정/연체는 일정에서 계산. 초안만 만들면 quoted로 바꾸지 않음 |
| Quote | draft → issued → approved / changes_requested / declined / archived. 만료는 유효기간 표시. 승인 문서는 새 revision으로 수정 |
| Job | unscheduled → scheduled → in_progress → completed / cancelled. 청구 필요는 청구 현황에서 계산 |
| Visit | scheduled → in_progress → completed / cancelled. 이동·배정 변경 이력 보관 |
| Invoice | draft → issued → void. 미납/부분납/완납/연체는 유효 수금과 만기일로 계산 |
| Timesheet | draft → submitted → approved. 반려 사유 기록, 승인 수정은 관리자 재개방 필요 |
| Expense | 생성·수정·보관. 별도 승인 절차는 추가하지 않음 |

발행·승인·취소는 서버가 허용 전이와 권한을 검증한다.
화면 버튼 숨김만으로 권한을 처리하지 않는다.

## 8. 권한과 데이터 분리

제안 기본 역할은 admin / supervisor 두 개다.
관리자는 전체 업무·견적·청구·직원·설정을 관리한다.
현장 담당자는 자신에게 배정된 일정·작업과 필요한 연락처, 자신의 비용·근무를 처리한다.
다른 사람의 급여·내부 원가·고객 청구 금액은 기본적으로 노출하지 않는다.
운영자가 더 넓은 현장 역할 권한을 원하면 권한표만 확정해 변경한다.

모든 노출 테이블에 RLS와 필요한 최소 GRANT를 설정한다.
활성 membership, 회사 범위, 작업 배정, 작성자를 업무별로 검사한다.
UPDATE는 기존 행과 변경 후 값을 검사하고 역할 자가 변경을 막는다.
인가에 사용자가 수정할 수 있는 user_metadata를 사용하지 않는다.

일반 업무는 인증 사용자 세션으로 처리한다.
privileged key는 브라우저에 넣지 않고 일반 CRUD의 권한 우회 수단으로 쓰지 않는다.
영수증은 비공개 Storage와 권한 검사된 파일 접근으로 제공한다.

별도 Supabase 연결값과 새 migration 이력을 사용한다.
원본 .env, Auth 사용자, Jobber OAuth 토큰, 운영 DB 설정은 복사하지 않는다.

참고 공식 문서:
- https://supabase.com/docs/guides/database/postgres/row-level-security
- https://supabase.com/docs/guides/auth/server-side/creating-a-client?queryGroups=framework&framework=nextjs

## 9. 화면과 반응형 제안

업무용 Operate 모드로 설계한다.
익숙한 Jobber 메뉴 순서와 상태→목록→상세 흐름을 유지하고 PBC 브랜드를 사용한다.
기존 견적 앱의 파랑 #0b66d8, 본문 #0f2440과 읽기 좋은 한글/영문 폴백을 참고한다.
Jobber 로고·녹색을 회사 고유 브랜드로 간주하지 않는다.

데스크톱은 사이드바, 검색/컨텍스트 헤더, 필터가 있는 업무 목록, 상세 화면을 공통화한다.
기본 화면에서 장식 카드보다 오늘 해야 할 작업·현장명·다음 행동을 우선한다.
긴 고객명·주소·한글은 필요한 정보를 잘라 모양을 맞추지 않는다.

좁은 화면은 접이식 내비게이션, 핵심 열 중심 목록, 날짜별 일정으로 구성한다.
견적 편집은 단계/영역을 접어도 총액·저장 상태·오류 위치를 확인할 수 있게 한다.
빈 상태, 로딩, 실패, 저장 충돌, 취소·미저장 입력을 명시한다.
키보드 순서와 시각 순서를 맞추고 최소 터치 영역·보이는 포커스·대비를 검증한다.

원본 Jobber 실데이터를 샘플 화면의 가짜 초기 데이터로 채우지 않는다.
개발용 예제는 샘플 표시와 별도 seed를 사용한다.

## 10. 일정·근무 시간

제안 기본 시간대는 Australia/Sydney이며 시각은 timestamptz,
종일 일정은 회사 현지 날짜로 관리한다.
DST, 자정, 여러 날 일정, 여러 방문, 미배정 상태를 검증한다.

인원 중복 배정은 경고를 제공하고 사용자가 확인해 조정한다.
인일을 임의로 8시간으로 환산하지 않는다.
직원당 실행 중인 타이머 하나만 허용한다.
수동 시간은 종료>시작, 휴게 범위, 다른 기록과의 중복을 검증한다.
승인된 근무는 관리자 재개방과 이력 없이 바꾸지 않는다.

## 11. 실패·복구·보관

주요 저장/변환은 트랜잭션, expected_version, 중복 요청 식별로 보호한다.
충돌·네트워크 실패 때 입력을 유지하고 다시 읽기·재시도 경로를 제공한다.
파일 업로드 실패와 레코드 저장 실패를 구분해 유실/고아 파일을 정리한다.
업무 기록은 보관/취소를 기본으로 하고 임의 영구 삭제하지 않는다.
발행 문서·수금·가격 확정·권한 변경 이력을 남긴다.

## 12. 구현 검증 기준

- 원본 코드·테스트에서 F1~F5, Roof, 영역, 미배정, 노무, 옵션, Timber와 반올림 결과 일치.
- historical-quotes.ts는 샘플 1건이므로 실제 과거 견적 검증으로 간주하지 않는다. 출시 전 비식별 확정 견적으로 원본과 EMS의 금액을 별도 대조한다.
- 가격/설정 변경 후 과거 승인 Quote, Job, 발행 Invoice 금액 불변.
- 고객 출력과 관련 응답에 내부 원가·메모·공식 미노출.
- 동시 저장 충돌·변환/발행 중복 클릭·재시도에서 부분 저장/중복 생성 방지.
- 실제 테스트 DB에서 비회원·비활성·타 회사·미배정 접근·행 ID 위조·역할 자가 승격 차단.
- 고객→요청→견적→작업→일정→청구/수금, 비용·근무 제출/승인 흐름 검증.
- Sydney DST·자정·종일 일정, 겹친 시간, 재접속 후 열린 타이머 검증.
- TypeScript, lint, 관련 단위/통합 테스트와 production build 통과.
- 데스크톱/중간/모바일 폭, 확대, 한글·긴 주소, 키보드·포커스·대비·주요 오류 상태 확인.
- 견적·청구 출력의 페이지 나눔·총액·연락처·Optional·내부정보 제외 확인.

아직 EMS 제품 코드가 없으므로 이번 조사에서는 위 테스트를 실행하지 않았다.

## 13. 출시 전에 확정할 사항

- 별도 Supabase 프로젝트의 대상/연결과 최초 관리자.

- 기존 Jobber 고객·작업·견적·청구·비용·근무의 이관 여부와 기준일.
